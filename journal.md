### FRIDAY | OCTOBER 23, 2026
This week we we learnt about Events and how to utilise them within our own code to make a program respond to external input. 

Across my three prototypes I used a timer (setInterval), key presses (keyPressed), the mouse wheel (mouseWheel) and mouse clicks (mousePressed), and combined them with variables and conditionals from earlier weeks. In the Hungry Plant, a timer shrinks the plant while key presses feed it, and an if/else chain changes its colour with its hunger. In the Sky Scroller - which I reworked from my Prototype 1 in our variables Week - scrolling moves the sun and the sky colour follows it. Then finally, the Typing Paint draws entirely from events and doesn't need draw() at all.

The biggest thing I learnt is that events run once per action, unlike checking something every frame in draw(). That made things like toggling a colour on click much more reliable. Events also made my programs feel more alive, because they only act when the user does something. It made it feel like you have more control on how the code can work, but how it can be specific to each users experience too. It certainly something I will continue to adapt and develop going forward.

### FRIDAY | NOVEMBER 6, 2026
This week I made three prototypes to help develop what we learnt on arrays. I made multiple flowers whose petals fall when clicked (refactored and improved code from last week), a fortune orb that shakes and gives random answers, and bubbles that keep rising while I pop them.

The thing that surprised me the most was how much simpler my flower became. In my functions prototype I had petal1 to petal6 written out by hand, with six update calls, six draw calls and six if blocks, which was a lot. Once I stored the petals in one petals array, two short 'for loops' did all of it so much easier. When I added two more flowers, I didn’t have to change the loops at all, even though there were suddenly 18 petals.

Something I found cool is that an array can grow while the program is running. In Bubble Rain, I used a timer which calls on a function that uses .push() to add a new bubble every 0.3 seconds, and the loop picks each one up automatically. I think it made the sketch feel alive in a way my earlier work didn’t.

One of the challenges I encourntered was the index. In my fortune orb, I had the condition backwards, so the index reset to 0 on every click and the message never changed. Working out that the last position is fortunes.length - 1, because counting starts at 0, helped make it click a bit more to me. I did also use the code from class to also help with my understanding of this as we did something similar with index.
